## v58.1 修复：手机开镜后战斗键被遮罩盖住

- 问题：手机点「瞄准」进入瞄准镜后，射击/瞄准/闪避等触屏按键全部"消失"，无法退出也无法攻击。原因是瞄准镜遮罩 `#scope55`（z-index 32）全屏覆盖，而触屏按键容器 `#touchUI`（z-index 8）在其之下；PC 不受影响（开镜后用鼠标左键射击）。
- 修复：`setScope55` 注入的样式增加 `body.scoping55 #touchUI{z-index:40}`，开镜期间触屏按键容器整体提到遮罩之上；遮罩本身 pointer-events:none，不拦截任何点击。
- 顺带：瞄准镜底部提示改为触屏适配——触屏设备显示「点『射击』发射五倍弹并自动退出 · 再点『瞄准』取消」，PC 仍显示原来的左键/右键提示。
- 机制不变：开镜单发伤害 ×5，射击后自动退镜；冷却中或空弹不误退镜；再点「瞄准」可主动取消。

## v58.2 全局基础伤害 ×5

- 新增单一调参点：`const PLAYER_DMG_SCALE=5`，`damageAmount(v)` 统一乘该系数（与 v31 风暴倍率 `stormDmg` 叠乘）。以后调平衡只改这一个数字。
- 作用范围：只放大**玩家输出**。全部 20 处 `damageAmount` 调用点核对过，目标均为怪物/BOSS 的 hp；玩家受伤路径（`playerHit`、`G.hp-=` 反伤/危险区）不经过该函数，敌人伤害不变。
- 修复连带发现的**倍率重复应用**问题（原代码在弹丸创建与命中结算各乘一次，风暴倍率同样被算了两次）：
  - 弹丸创建（普攻弹 / 蓄力弹）不再预乘 `damageAmount`，改由命中结算 `p.dmg` 处统一结算一次；
  - 蓄力弹冲击波与震荡弹头溅射原本对已结算的 `dealt` 再乘一次，改为直接取 `dealt*.6`，恢复"溅射=直击 60%"的设计语义。
  - 若不修，远程武器会吃到 ×25、近战/技能只吃 ×5，武器间失衡。
- 数值效果（`qaImpact55` 固定随机因子的真实碰撞扣血，对照 v55 文档基准）：

| 角色 | 修复前普攻 | 现在普攻 | 现在开镜单发 |
| --- | --- | --- | --- |
| 调查（explorer） | 2.56 | 12.8（×5） | 64（普攻 ×5） |
| 突击（hunter） | 4.4 | 22（×5） | 110（普攻 ×5） |

- 注意：开镜单发在"全局 ×5"之上仍是普攻的 5 倍，即相对最初版本为 ×25。若要压低，改 `PLAYER_DMG_SCALE` 或把 `fireFromCamera` 里瞄准分支的 `res.dmg*=5` 调小即可。

## v58.3 爆头：命中头部算暴击，并在暴击之上再 ×2

- 规则：玩家弹丸（普攻 / 蓄力）命中**头部** → 必定暴击（×2），并在暴击倍率之上再乘 `HEADSHOT58.mult`（默认 2）→ 合计 ×4。近战扇击、角色技能、元素反应不参与爆头。
- 头部区间不写死高度：怪物建模后按**网格包围盒**算出 `head58.head = 模型底部 + 身高 × 72%`（相对地面），体型变体自动适配。实测各类型头部下沿（相对地面）：雷群 1.098 / 灰手 1.358 / 溅射者·酸水 1.413 / 飞镖 1.421 / 精英 1.581 / 甲盾 1.664；合成目标（QA、召唤）无包围盒数据时用 `fallback=1.15` 兜底。
- BOSS：其命中判定只算水平距离，故用 `HEADSHOT58.boss` 类型表给头部高度（含悬停）：reefCrab 1.95 / kelpLeviathan 2.8 / abyssJelly 5.1 / voidWhale 3.3 / hand 2.4 / handX 2.9。首版估算值，可按实战体感调。
- 表现：爆头伤害数字为橙色「爆头!」大字（高于普通暴击的金色「!」），并附带专属回声环、镜头轻震与触屏振动；装备库「最近命中」也区分显示「爆头」。
- 调参：`HEADSHOT58 = { forceCrit, mult, frac, fallback, boss }` —— `mult:1` 即"只算暴击 ×2"，`frac` 调头部区间高低。

## v58.4 单文件版压缩到 20MB 以内（57.7MB → 15.19MB）

原单文件 57.7MB，其中 52.2MB 是人物包 `packed49.js`。逐项分析后按「视觉无损优先」压缩：

| 内容 | 原大小 | 处理后 | 手段 |
| --- | --- | --- | --- |
| 模型 hair | 28.25MB b64 | 7.33MB b64 | weld + quantize（KHR_mesh_quantization）→ gzip |
| 模型 body | 8.15MB b64 | 3.00MB b64 | 同上 |
| 模型 head | 3.89MB b64 | 1.22MB b64 | 同上 |
| 6 张 1k PNG 贴图 | 11.90MB b64 | 2.23MB b64 | WebP（opacity 遮罩用无损，其余 q85） |
| 菜单海报 | 3.37MB b64 | 0.27MB b64 | WebP q86 |

- **量化（quantize）**：属性 float32 → int16/int8（归一化），模型高约 1.5m 时位置精度约 23µm，肉眼不可见；three.js r149 的 GLTFLoader 原生支持该扩展，无需 Draco/meshopt 解码器。顶点数、三角面数、骨骼数完全不变（79 网格 / 652,622 顶点 / 429,982 三角面 / 52 骨骼，与原版一致）。
- **gzip 内联 + 运行时解压**：Python 侧 `gzip.compress(level=9)`，base64 内联；运行时用 `DecompressionStream('gzip')` 解压（需 Chrome/Edge 80+ 或 iOS Safari 16.4+，不支持时给出中文提示）。贴图/海报是 WebP，本身已压缩，直接以 data URL 内联、不再 gzip。
- **构建缓存**：中间产物在 `.cache_vit49/`（约 10.6MB），源 `packed49.js` 未变时直接复用，跳过 gltf-transform；`D3D_NO_MIN=1` 可回退到原样内联（约 57MB）。
- **不改源资源**：文件夹版（`潮声之下_深渊潜航3D_v22.html` + assets/）保持原样，压缩只发生在单文件构建产物里，`characters49.js` 的解压钩子也是构建时注入。

踩过的两个坑（都已修）：
1. Python `zlib.compress` 产出 zlib 容器，而运行时按 gzip 解压 → 报 “Failed to fetch”；改用 `gzip.compress`。
2. 解压钩子写成了立即执行表达式（赋值 Promise 而非函数）；且 `characters49.js` 在 IIFE 之后立刻把 `VIT49_DATA` 置空，存在竞态 → 改为「定义为函数 + 返回解压结果」。

另外修了 `test_scope55.cjs` 的一处不稳定断言：换关瞬间主线程在重建 65 万顶点人物模型，原测试左键射击后固定只等 100ms 就读状态，偶发读不到 → 改为最多 5s 轮询等待。
