# 本次更新 · v56 —— 网页版封装为 Windows 桌面程序

更新时间：2026-09-16
类型：交付/工程化（不改游戏玩法与美术）

## 一句话

在 `desktop/` 里用 **Electron** 把 `潮声之下_深渊潜航3D_v22.html` + `assets/` 封装成
**双击即玩的 Windows 程序**：自带本地服务器与联机中继，目标机器不需要浏览器、不需要 Python、
不需要再运行 `启动联机.bat`。

## 为什么不用 `file://` 直接打开

三个硬性原因，决定了必须内置一个本地 HTTP 服务器：

1. `assets/environment/*.js`、`assets/vitruvian/*.js` 是按「站点根 + 相对路径」加载的，
   `file://` 下有被同源策略拦掉的风险 → 白屏；
2. 游戏里有 `fetch('/health')`，`file://` 下必然失败；
3. `netConnect()` 显式要求 `location.protocol` 是 `http/https`，否则直接提示
   「请先运行 Python 服务器」→ 联机在 `file://` 下根本点不动。

于是桌面版先起 `http://127.0.0.1:8123/`（端口与 `启动联机.bat` 一致），再让窗口指向它。
`/health`、`/ws` 也一并由 Node 实现（`src/relay.js` 是 `联机服务器.py` 的等价移植，
`service=tide-coop`、`protocol=2`、房间上限 2 人），所以**桌面版自己就是主机**。

## 杀毒软件误报（实测记录）

本机装的是**卡巴斯基**（`avp.exe`），实测行为：

- 打出来的 `dist/潮声之下_安装包_1.0.0.exe` 被**直接删除**，目录里只剩 `.blockmap` 旁文件；
  同一目录的免安装 `潮声之下_1.0.0_x64.zip` 与 `win-unpacked\潮声之下.exe` 存活。
- 打包过程中实时防护会扫描/短暂锁定新写出的文件：曾出现构建**卡在 `copying Electron`**
  （`win-unpacked` 里只有 `locales/`）、临时目录里的大文件删不掉的状况。
  无干扰时一次完整打包约 **50 秒**，超过 3 分钟没进展基本就是被拦。

工程侧已做的降误报措施：

- `nsis.allowElevation: false` + `nsis.packElevateHelper: false` → `resources/` 里不再有 `elevate.exe`（已实测确认）
- 写入完整版本信息：`CompanyName` / `FileDescription` / `ProductName` / `LegalCopyright` / `LegalTrademarks`
  （已用 UTF-16 资源字符串检测确认写入应用 exe 与安装包 exe）
- 不加壳、不混淆，不生成误报率最高的 `portable` 单文件版
- 新增 `npm run checksums` → `dist/SHA256SUMS.txt`，用于核对文件是否被删、以及提交误报申诉
- 新增 `npm run clean`（`scripts/clean.mjs`）：**打包卡死的真正原因**是
  electron-builder 打包前 `emptyDir(dist/win-unpacked)` 删不掉上一版被杀的软扫描占用的大文件，
  于是无限重试（表现为"卡在 copying Electron"）。现在所有打包命令都会先清理，
  删不掉就把 `dist/` 改名让路（`dist.locked-<时间戳>`），打包 1 分钟内必出结果。

分发与处理建议（README §8 有完整三步 + 申诉入口）：

1. **优先发免安装 zip**，并在解压前先加杀软排除项（顺序反了会在解压瞬间被删）；
2. 卡巴斯基：设置 → 安全威胁与排除项 → 排除项；已被隔离的去「更多工具 → 隔离区」恢复；
3. 根治办法只有一个：上 **OV/EV 代码签名证书**（自签名无效），配置 `CSC_LINK`/`CSC_KEY_PASSWORD` 即可，
   务必带时间戳（`/tr`）。

## 环境坑（已写进 README，换机器时会用到）

- 国内 `github.com` 不通 → `npm run prepare-binaries` + 设 `ELECTRON_MIRROR`（本次即用此法成功）。
- `electron-builder.yml` 里用 `electronDist: node_modules/electron/dist` 复用已装好的 Electron，
  避免某些环境从 zip 解压不完整导致 exe 缺 `ffmpeg.dll` 而无法启动。
- 启动 Electron 前要清掉 `NODE_OPTIONS`（带 `--use-system-ca` 会被 Chromium 拒绝）
  和 `ELECTRON_RUN_AS_NODE`（会导致 `require('electron')` 拿不到 `app`）。
- 无显卡/受限环境会报 `GPU process isn't usable`，加
  `--disable-gpu --enable-unsafe-swiftshader --disable-gpu-sandbox --no-sandbox` 可用软件渲染跑通并截图。
- electron-builder 解压 winCodeSign 时因归档内 macOS 符号链接失败；`prepare-binaries` 已自动排除
  `darwin/`、`linux/` 目录规避（手动做法：解压到
  `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\winCodeSign-2.6.0`）。
- 打包版是 GUI 程序、没有控制台输出，排查看 `%APPDATA%\潮声之下\logs\main.log`。
