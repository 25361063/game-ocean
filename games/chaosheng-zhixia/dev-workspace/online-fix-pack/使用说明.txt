潮声之下 · 联机修复 v3.1（全队任务与传送）
更新日期：2026-09-06

一、启动
1. 关闭此前的联机服务器窗口。双击本目录“启动联机.bat”。
2. 主机需要 Python 3.10+。脚本使用本目录 .venv 环境，首次缺少依赖时自动从官方 PyPI 安装。
   本机环境已安装好。换电脑请勿拷贝 .venv，让启动脚本在新电脑创建。
3. 窗口应显示“3.1-coop-stages”。保持窗口开启。
4. 主机打开 http://127.0.0.1:8123。
5. 另一台设备打开窗口显示的“另一台设备打开”地址。切换热点后 IP 会变，请重新启动并使用新地址。
   另一台设备不需要运行服务器，两边都应访问主机上的这一份服务。
6. 主机点击创建房间，显示“连接成功 · 1/2 人”；另一端输入该房间号点击加入。
   两边显示“连接成功 · 2/2 人”后，选择相同关卡、难度，各自开始并推进开场剧情。
7. 端口冲突时在终端运行：启动联机.bat 8124，然后用窗口里带 8124 的地址。

二、连接失败时
点游戏里的“连接失败？打开联机诊断”，或打开 http://主机IP:8123/diagnostics。
诊断会依次测试：HTTP 服务身份、WebSocket 握手、房间回执、双向心跳。
两台设备分别运行，并记录哪一项失败。主机的“联机运行.log”会记录请求、连接、加入和关闭。
日志保留在本机，网页不能下载日志或项目源码。

- 本机诊断全部通过、另一台连诊断网页也打不开：核对新 IP、端口、当前网络配置下的 TCP 入站规则。
- HTTP 404 / 版本不匹配：旧服务器还在运行，或打开了其他静态网页服务器。关闭旧窗口并运行新版。
- HTTP 通过但 WebSocket 失败：记录关闭码及日志，检查代理/浏览器对 WebSocket 的限制。
- 两边一直 1/2：确认同一服务器地址和完全相同的房间号，不要各自运行一份服务器。
- 显示房间已满：关闭多余的游戏标签页，最多两人。

三、防火墙检查
本次读取到原有 Python 放行规则仅对 Public 网络生效，不足以证明换热点后的配置仍匹配。
新版使用 .venv 中的 Python，防火墙规则也应与实际运行环境匹配。
仅在“主机诊断通过、另一台网页打不开”时，可在本目录的管理员 PowerShell 中运行：
  .\允许局域网联机.ps1
它只添加 TCP 8123、来源为本地子网的规则，覆盖各网络类型，不关闭防火墙。
自定义端口用：.\允许局域网联机.ps1 -Port 8124
撤销用：.\允许局域网联机.ps1 -Port 8123 -Remove
此脚本本次没有执行。若系统组织策略禁止本地规则，需要管理员处理。

四、这次更改
采用 https://github.com/aio-libs/aiohttp 的成熟 HTTP / WebSocket 框架，锁定 aiohttp 3.13.3。
保留游戏的固定玩家 ID、双人房间和原有消息格式，替换手写帧处理。
加入健康检查、分阶段错误提示、可独立访问的诊断页和滚动日志。
原来的四个文件已保存在“修复前备份”目录。

六、游戏与公网限制
人物外观更新：增加面罩、胸甲、气瓶束带、呼吸管、护膝和腕部仪表，调整角色装备。
队友显示更新：修正高度/朝向，增加平滑位移转向、步行动画、角色姓名和按最大生命值计算的血条。
短暂暂停时保留队友模型，跨关或长时间失联隐藏；传送距离过大时直接校正位置。
启动服务器后访问 http://127.0.0.1:8123/characters 可旋转预览三种角色；按 V 查看本地第三人称模型。
模型测试：node test_characters.cjs。已检查实际浏览器预览，尚未在两台物理设备上验证网络延迟下的视觉效果。

关卡证据、击杀、扫描、防守、计时和任务完成状态同步。任一玩家完成任务，全队舱门解锁。
任一玩家进入已解锁的舱门，房主统一确认后全队一起进入下一关，不要求队友走到门前。
末关由任一玩家通过，全部玩家获得胜利结算；暂停或死亡的队友也接收换关/胜利。
联机换关直接传送，跳过单机的过关剧情、过关事件选择与下一关开场对话；本关内事件仍独立。
扫描和防守由房主统一计时，任一活跃玩家在区域内即可推进；联机进度不因离开区域倒退。
增援波次由房主推进。装备/商店、生命和存档仍独立，传送保留各自装备、金币和分数。
双方首次仍需进入相同关卡。无尽模式的波次/奖励不在本次关卡传送修改范围。
邀请码直连仍是原有备选实现，没有新增 TURN 中继，不保证跨网可用。
aiohttp 是服务器软件，不是免费的公网托管；本包未部署云端服务器。
